| 4 | ⭐ **歌词 × 编曲打通**（`set_vocal_melody` 或 `export_groove` 接受 `arrangementId`） | 歌词绑在 **v1 song**、编曲在 **v2 arrangement** ⇒ ⭐ **没有任何一个成品工程同时含"怎么编"与"怎么唱"** ✗ | 二选一：① `set_vocal_melody` 接 `arrangementId` ✓ ② 或 `export_groove` 接 ✓；⚠️ 代价＝**入参／存储／导出／两套判据** 四处 ✓ | 大（**跨 v1/v2 边界** ✓，需先量清歌词落地层 ✓） |

## 三、⭐ 不方便，但不算 bug（体感类 ✓）

```
① ⭐ **错误信息只说失败、不说"该改哪一步"** ✓ —— 渲染失败时给的是渲染期错误 ✗，
   而真正该改的是**音域/音符** ✓ ⇒ 建议：错误里加一句"**先跑 `get_pitch_report`**" ✓
② ⭐ **长任务没有心跳** ✓ —— 112 s 里 MCP 客户端**只看到一个静默等待** ✗
   ⇒ 带 `progressToken` 时报进度 ✓（已有 ✓），建议**默认也报** ✓
③ ⭐ **单位与口径要反复猜** ✓ —— 音高是 MIDI 号还是音名 ✓／增益是 dB 还是线性 ✓／
   时间是秒还是小节 ✓ ⇒ 建议：新增工具时**在描述第一句写明单位** ✓
④ ⭐ **落盘位置不总显式** ✓ —— 有的工具回包给绝对路径 ✓、有的只给文件名 ✗
   ⇒ 建议统一"**绝对路径 ＋ 字节数**" ✓（MCP 侧自描述纪律 ✓）
```

## 四、⭐ 明确不存在的能力（**不要假装有** ✗）

```
① ⭐ **人声合成不存在** ✓ —— `synthesize_vocal` 自述 `reserved — not implemented` ✓；
   采样库 `Vocals` 只有**死亡金属人声／怪物念白／pre-drop** ✗ ⇒ ⭐ **没有歌唱采样** ✓
   ⇒ 两首歌的主旋律由**口琴**（民谣 ✓）与**次中音萨克斯**（R&B ✓）代唱 ✓
② ⭐ **Logic / 记谱软件的"真机打开"未证** ✓ —— 工程与 MusicXML **已生成** ✓，
   但**未在 Logic 打开** ✗、`.groove` **未回导** ✗、MusicXML **未用记谱软件打开** ✗
③ ⭐ **浏览器渲染路径只跑了冒烟** ✓ —— 正式渲染全部走 headless ✓；
   浏览器侧只跑过 1 次 **8 kHz mono preview** ✓
```

## 五、⭐ 下一步：给 agent 的创作 skill

```
⭐ 目标 ✓：把"**从零创作一首歌**"的**顺序、陷阱、判据**写成 skill ✓（与 `groove-dev-workflow` 并列 ✓）
   已归拢的骨架 ✓：
   1. **先量后写** ✓：写音符前先 `get_pitch_report` 解析一个音 ✓（音域无处可查 ✓）
   2. **便宜探路优先** ✓：`dryRun`／preview ⇒ 别直接整曲渲染 ✓（2 分钟/轨 ✗）
   3. **同一个测量别跑两遍** ✓：`spectral_balance` 与 `analyze_audio` 同一份分析 ✓
   4. **响度口径要写清** ✓：集成响度 vs 真峰 vs 采样峰 ✓（本次 −1.300 曾被误称真峰 ✗）
   5. **分析是同步的** ✓：一次 87–112 s 内服务端不响应 ✓ ⇒ 别并发廉价调用 ✓
   6. **不存在的能力要说出来** ✓：人声合成 ✗ ⇒ 用器乐代唱并**在交付里写明** ✓
   7. **交付自描述** ✓：绝对路径 ＋ 字节数 ＋ 关键读数 ＋ **未测项** ✓
```
