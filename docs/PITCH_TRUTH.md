# 音高真相：一个真相、处处显式、随时可撤

**业主定的方向（2026-10-01，逐字）**：

> 不要试图"保证用户永不搞错"，而是让系统内部**只有一个音高真相**，**所有可能移调的地方都显式、可见、可撤销**。

> MIDI 文件本身只存 MIDI Note Number 0–127，并不存"C3/C4/C5"这种名称。**导入时天然差八度，通常不是 MIDI 文件错，而是软件显示、音源根音、自动移调、鼓轨处理等环节出了问题。**

这份文档是同名目标的**第一步：对着业主要求逐条审计**（§1），然后才是交付（§2 起）。

## §2 绝对音高普查（业主 2026-10-01 补充要求的交付）✓✓

**业主的原话** ✓："**但是也不要排除有部分音源标记错误哦，我们登记和使用的，我们都应该检测绝对音高**"

**⇒ 正确的量法** ✓✓：**"绝对音高对不对"就是"给引擎一个音符、它出的频率对不对"** ✓——**因为引擎信的是采样标签；标签错，输出就错** ✓。**而引擎实际选中的是哪个文件，由 `resolved` 自报** ✓✓（**这一点至关重要：她的表点的是 `v1`，而引擎用的是 `v2`/`v3`** ✗✓）。

**方法** ✓：经真 MCP 的 `render_instrument_note`（1.2 秒）→ 读回 WAV → **归一化自相关、两个独立窗**（0.25 s 与 0.7 s 各起一段）→ **`clarity` 低于 0.5 或两窗相差 >40 音分即弃权** ✗✓；**先自校准**（已知正确的资产必须全绿 ✓），**再去判未知** ✓。

## §5 决定：Ableton 导出里的 `C3` **不改**，而是**把约定点名并钉住数字** ✓✓（2026-10-01）

**问题** ✓：`src/audio/AbletonExporter.ts` 的 `TRACK_MIDI_MAPPINGS` 把 36/48/60/72 注释成 **C1/C2/C3/C4**，而项目别处默认 **C4 = 60** ✗——**同一份代码里两套未标注的约定** ✓。

**先查清两件事，才谈取舍** ✗✓：

1. **那些注释本来就自洽** ✓：36→C1、60→C3 正是 **`C3 = 60`**（Ableton/Yamaha 的命名 ✓），**不是笔误** ✓；
2. **`baseNote` 是承重的数字** ✓✓：`AbletonExporter.ts` 里 `pitchOffset = defaultMap.baseNote + pitchOffset` ✓——**它决定导出的移调量** ✓。

**⇒ 两个错法都排除** ✗✓：

* **把注释改成 C4** ✗——**那会让文档对目标 DAW 变错**（打开文件的人看到的正是 C3 ✓），**用一套约定去覆盖另一套没有让任何人更清楚** ✓；
* **把 60 改成别的以"对齐名字"** ✗✗——**那会移调音乐** ✓，**正是这场工作存在的理由反过来打自己** ✓。

**⇒ 采用了第三个做法** ✓✓：

* **`export const ABLETON_NOTE_NAMES: "C3" = "C3"`** ✓——**约定成为一个具名事实，而不是从注释里推断** ✓；
* **表上一段 docstring** ✓：**这些名字是 Ableton 的命名（note 60 是 C3）** ✓、**项目别处默认 C4** ✓、**两者不是矛盾而是"同一批数字的两种读法"** ✓、**`baseNote` 会变成 `pitchOffset`，因此不能为了标签动它** ✓；
* **`MidiExporter.ts` 里那张同构表**（**没有音名注释 ✓**）**加一段说明**：**音名只写在 Ableton 那张表上，第二套标注就是第二个会漂移的地方** ✓；
* **判据**（`src/test/pitchConvention.test.ts` ✓）：**约定名为 `"C3"`** ✓、**36/60/72 在该约定下是 C1/C3/C4** ✓、**同样三个数字在 C4 下是 C2/C4/C5**（**这就是"点名"的价值 ✓**）、**以及八个 `baseNote` 逐一断言** ✓✓。
