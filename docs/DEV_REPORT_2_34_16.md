## 三、行动清单（按报告的分级）

1. **P0.1 —— 渲染的可观测性**：给 `render_song` 一条**心跳/进度**通道（至少"已渲染 N/M 小节"），并把**预期耗时量级**写进描述（"每分钟音频约需 X 秒"，X 用本仓库实测而非估计）；
2. **P1.2 —— 错误信息指向能力**：`create_song` 在 genreId 未知时列出**可用 id**（或前 N 个 + `list_genres` 指引）；
3. **P1.3 —— 标准流程**：在 prompt 或文档里给出 `create_song → set_clip → add_lane → add_section → set_tempo → render_song` 六步，每步一句话；
4. **P2.5 —— 长 pattern 的真相**：核实 `create_song` 能否接受 128 步；能就在描述里写明，不能就说明上限与替代法（乐句链）；
5. **P2.6 / P2.4 —— 上限与槽位**：评估 `MAX_SONG_BARS` 与四槽位是否仍是必要约束（这是**设计决定**，需要业主拍板；我会在核实后给出"拆成两次渲染"的替代指引作为不阻塞的答案）；
6. **P3.7 —— 构建产物的一致性**：在 CI 里断言 `dist-mcp` 与源码版本一致（把它从"靠运气"变成"靠门禁"）；
7. **P3.8 —— 变速示例**：给 `set_tempo` 一个三段式完整例子。
