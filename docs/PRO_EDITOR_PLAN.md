# 专业编辑器方向 —— 计划

产品的定位变了：**它是一台 Logic Pro 那样的音乐编辑（制作）软件，步进音序器只是其中一个编辑器**。这条方向是
owner 明确说的，也说明了一件事：**音准与听感优先于格子系统**。本文写下这个转向在数据、引擎、界面与导出上的
具体含义，以及分阶段怎么做，避免它变成一句口号。

## 一、现在被"步进器"限制住的地方

库里的每个声部今天都表达为**步进数组**：`steps[]`（这一步响不响）、`pitch[]`（这一步的音高）、`velocity[]`、
`gate[]`。由此带来三个硬限制：

1. **时值只能是 16 分格的整数倍**——一个附点、一个三连音、一个 0.7 拍的长音都表达不出来；
2. **起音只能落在格上**——swing 只能整轨偏移，做不出"这一拍稍微推后一点"；
3. **音的属性绑在格上**——同一个格子里不可能有两个不同时值/力度的音（ratchet 是特例，不是通例）。

而"啪"这类听感问题（见 `GROOVE_QUALITY_PLAN.md` 与 `SYNTH_UPSTREAM_PLAN.md`）说明：**当音符长度被格子决定时，
乐器的起音/释放就没有地方商量**——这正是把"音的属性"从格子里解放出来的理由。

## 二、目标模型：音符列表是真相，格子是它的一个视图

```
Note = {
  trackId, pitch, startSec (或 startTicks), durationSec,
  velocity, pan?, cents?,      // 已有
  articulation?,               // 可选：来自段落/曲风的奏法
}
Clip = { lane: MixTrackId, notes: Note[], lengthBars }
```

- **格子视图**：把落在同一格（容差内）的音符显示成格子；用户在格子里画，写回的是音符（量化为该格中心）；
- **卷帘/钢琴卷视图**：直接显示音符的起止与音高（可离格）；
- 两者编辑的是**同一份数据**，不存在"格子数据"与"音符数据"两份。

迁移上不需要一次性重写：`steps/pitch/velocity/gate` 保留为**导入/生成**的表达，载入时展开成音符；
保存时若全部音符都落在格上且属性一致，可以回写为格子（保持旧文件与分享链接的形状）。

## 三、引擎侧：现在就能做什么，缺什么

好消息是**核已经支持按帧寻址**（`noteAt` / `noteOnAt` / `noteOffAt`，绝对帧），也支持逐音
力度、声像、音准（ABI 9 的 `cents`）。所以离格、附点、三连音、微推后都可以直接表达——**不需要新的 ABI**。

缺的（已记入 `SYNTH_UPSTREAM_PLAN.md`）：

- 逐音**滤波器**（若某音要单独更暗/更亮）；
- 逐音**包络**（一个音要短促、另一个要拖长尾）。

在这两样之前，"时值"已经能改变听感的大部分——因为核的包络是按**门长**走的（这正是上一轮"起音对齐"规则做的事）。
所以第一阶段**不依赖上游**。

## 四、分阶段

**P1：音符层（不依赖上游）**
1. ✅ `src/data/noteLayer.ts`：`LaneNote` 数据结构 + 展开（`notesFromLane`，含和弦堆栈与 ratchet 细分）与回写
   （`laneFromNotes`）。回写规则**只拒绝格点说不出来的东西**：起始位置必须落整步（1.5 步起音不行）、同一格上的音必须
   力度与时值一致（那是"一个事件多个音高"，不是序列）；**时值可以是任意小数**（`gate` 本来就是浮点）。说不出来时返回
   `null`，而不是四舍五入——被量化的那条轨正是需要音符层的那条。回写遵循曲库自身的约定（未触发步力度为 0、`gate`
   等于默认 0.8 时不写该字段），所以格上轨道能**逐字段往返**。全库实测（`src/test/noteLayerCatalogue.test.ts`）：
   **159 个曲风 × 8 条轨 = 1272 条轨中，1236 条有音符的轨全部逐字段精确往返，0 条被拒**，其余 36 条是空轨（没有任何
   触发的步）。也就是说这条迁移路径**对现有曲库是无损的**——写回规则的严格性没有让任何一条现有轨付出代价；
2. `planGs1Notes` 与导出器接受 `Note[]`（它们本来就是"音符 + 帧"的形状，接口几乎不变）；
3. 引擎的调度从"按步触发"改为"按音符触发"（保留步进路径作为生成器）。

**P2：格子视图与音符视图并存**
4. 现有步进器继续工作，但读写的是音符；
5. 新增最小卷帘：显示/拖动音符的起点与长度，音高上下拖；分轨各一行（这也正是分轨编排欠缺的那一块，见
   `ARRANGEMENT_PLAN.md`）。

**P3：专业编辑器的其余部分**
6. 量化/摇摆作用于音符（而不是整轨）；
7. 复制/粘贴/框选/多选、撤销粒度按音符；
8. 段落与音符的交互：段落覆盖仍是"整段属性"，音符是"段内内容"。

## 五、必须守住的

- **步进器不能退化**：格子视图仍要能一键画出整条鼓型（这是它最有价值的地方，不该为了"专业"而删掉）；
- **旧文件与分享链接不变形**：回写规则要在测试里锁住；
- **导出与实时一致**：`planGs1Notes` 是唯一入口（这是既有契约，见 `WavExporter` 的 parity 注释）；
- **预算**：音符模型会增加包体（每首歌曲的注释数据），分阶段做并在 `check:budgets` 的框架内；
- **不因为"格子做不到"而砍掉音乐需求**：遇到冲突时，改数据模型，不改音乐。

## 六、与当前工作的关系

- 音色/响度那批工作（`GROOVE_QUALITY_PLAN.md`）**先行**：它决定"同一个音在不同曲风里应该听起来怎样"，
  是音符层的地基（没有它，离格只会放大不好听的音色）；
- 分轨编排（`ARRANGEMENT_PLAN.md` 第一刀）与本文 P2 的"每轨一行"是同一件事的两半：**一行轨 + 行内音符/片段**；
- 上游队列（`SYNTH_UPSTREAM_PLAN.md`）只在需要逐音滤波/包络时才动。
