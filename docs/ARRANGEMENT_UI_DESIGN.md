# 编排界面的设计依据

业主的要求（2026-09-30）：

> Web编排界面这块，你可以搜索借鉴学习成熟的这类软件、最优秀的那种或者行业标杆的设计和布局，然后再把我们特色的东西整合进去就好，不要重复造轮子

所以这份文档只做一件事：**说清哪些是业界惯例（照做）、哪些我们有意不同（写明理由）、以及我们独有的东西放在哪里（不破坏惯例）**。每条惯例都引一手手册，出处见文末；引用是读原文得到的，不是二手转述。

## 1. 编排界面的分区

**几乎人人如此**（REAPER 手册 §1.12/§1.26 把主窗口直接叫 Track Control Panel + Arrange Area；Bitwig UG §3.1.1/§3.1.3 叫 Arranger Timeline Panel，节拍尺在上、轨道头在左；Cubase 手册把工程窗口描述为"工具栏、轨道列表、带标尺的事件区"）：

- 时间从左到右，轨道自上而下堆叠；
- **左侧轨道头列 + 右侧通道区**；
- **标尺只在通道区上方**（轨道头列上方没有标尺）；
- 顶部全局走带条。

**各家不同**：轨道头上给推子还是给混音送出（Live 可配置）、标尺单位（Live 同时给小节与小节/分秒）、通道里是否画音符（Live 画，FL 只在 Tile 模式画）、分组模型（Logic 的 Track Stack / Live 的 Group）、是否有模态工具面板（Bitwig 1–5、FL 工具、Cubase 工具箱；Live 与 Logic 是无模态的）。

**我们采纳**：分区照惯例；**标尺只跨通道区**；**不做模态工具面板**（它们各需一个快捷键且与触摸相冲）。

## 2. 轨道头：最小集合与顺序

| DAW | 手册记载的顺序 |
| --- | --- |
| Bitwig | 颜色条 → 类型图标 → 名称 → 音量推子 → 录音臂 → solo → mute → 自动化按钮 → 电平表 |
| REAPER | 录音臂、路由、FX 链、trim、pan、名称、音量、mute、solo；**TCP 可调宽，变窄时控件会被隐藏** |
| Live | 音量、pan、I/O 等可配置；activator `0`、arm `C` |
| Cubase | 轨道列表显示名称与设置，**Track Controls Settings** 决定每个轨道类型显示哪些控件、**顺序**与分组 |
| Logic（iPad） | 编号 + 图标 + mute/solo/音量/pan/录音；其余在 Inspector |
| FL | 名称/颜色/图标，一个 Mute/Solo 图标（点击=mute，右键=solo）；可选 Track Mode 绑定 Instrument ↔ Playlist ↔ Mixer |

**专业用户预期的最小集合**：名称、颜色、mute、solo、录音臂、电平，以及**一条通向乐器/FX 链的路**。

**我们采纳 Bitwig 的顺序**（它是唯一把顺序写进手册的）：颜色条 → 类型图标 → 名称 → 音量 → 录音臂 → solo → mute → 电平表；**乐器槽也放在轨道头上**（见第 6 节），这正是 Cubase 放可配置轨道控件、FL 用 Track Mode 绑定乐器的地方。

**我们有意不同**：REAPER 的"变窄就隐藏控件"在触摸设备上不可接受。**当时**的做法是在**手机上把控件移出轨道头（底部抽屉），而不是缩小它**（WCAG 2.5.5/2.5.8）——**那条底部抽屉随手机外壳在 `4dffdf0` 一起砍掉了** ✗✓，今天窄屏与触摸设备拿到的是同一套桌面工具条（`docs/OPEN_WORK.md` §十三）。这一点没有 DAW 手册可循，是我们的判断。

## 3. 标尺与时间

| 惯例 | 手册怎么说 |
| --- | --- |
| 标尺单位随缩放变化 | Bitwig：`BAR` → `BAR.BEAT` → `BAR.BEAT.TICK`，随缩放改变 |
| 缩放呈现 | Bitwig：在刻度数字上上下拖（光标变放大镜）、`+`/`−`、Ctrl+Alt 拖、触控板捏合；Live：`+`/`−`、Ctrl+wheel、`Z` 缩放到选区、`X` 退回 |
| 播放头 | **Bitwig 把 Global Playhead 与 Play Start Marker 分成两个指示**（黑线 + 标尺上的蓝色三角）；Live 是闪烁的插入标记，`Home` 归位 |
| 循环区间 | Live：循环开关 + 标尺上的 loop brace，`Ctrl/Cmd+L`，方向键微调、Ctrl+方向键改长度；Bitwig：拖中间移动、拖两端改长度 |
| 标尺上的点击/拖拽 | Live：拖=横向滚动、纵向拖=缩放、双击=缩放到选区；Bitwig：单击标尺上半=设置播放起点 |
| 吸附 | Live：**网格间距显示在标尺右上角**，`Ctrl+4` 开关，Alt/Cmd 临时绕过 |

**我们采纳**：标尺标签随缩放从"小节"变到"小节.拍"；**播放头与播放起点是两个指示**（Bitwig 的做法，且我们的 DOM 已经有播放头样式）；标尺在右上显示**当前吸附值**；吸附开关 + 绕过键。

## 4. 通道里画什么（这是最要紧的一个设计问题）

七款软件在编排层面对待的都是**区域/片段**，不是裸音符：Live 手册 §6.7"一段音频或 MIDI 在编排视图里表现为某个歌曲位置上的一个 clip"；Bitwig §3.1.1"Arranger clip"；FL 的 Playlist 装的是 pattern clip / audio clip / automation clip。

但通道**确实画内容预览**：Live 反复提到点击/拖拽"clip 的波形或 **MIDI display**"；FL 有显式选项 View → "Content in title bars"。

**真正该照抄的是可编辑边界**：Live §6.7 明确"只有 clip 条可以拖，不能从波形或 MIDI display 上拖"。编辑在 Clip View 或展开轨道之后进行。

**所以我们这么做**（模型里 `notesByTrack` 是每轨一个扁平 `NoteEvent[]`，唯一的区间类型是 `TakeRegion`）：

- 通道里画**不可编辑的缩略**：x = `startBeats`，y = 该轨自身音域归一化后的音高，宽 = `lengthBeats`，透明度 = 力度；
- **区域条是拖动/选择/切分的把手**，缩略图不是。

**这是一个真实的设计决定，不是细节**，两条路都写在上面：
- (a) **现在**：每轨派生一个覆盖 `1..arrangement.bars` 的区域（如实的摘要，模型零改动）；
- (b) **以后**：把 `TakeRegion` 的 `{startBar,endBar}` 提升为通用的区域模型，让 take 与音符共用。

**我们先做 (a)**，因为它不撒谎也不改模型；等"一段一段的编排"成为真实需求时再做 (b)，那时它会有具体形状。

## 5. 我们有意不抄的

- **在通道里编辑区域内容**（Live 明确禁止）——抄边界，不抄可编辑；
- **模态工具面板**（Bitwig 1–5、FL、Cubase 工具箱）：五个隐藏模式，每个都要快捷键，且与触摸冲突；
- **触摸设备上 24 px 的轨道头控件**（Live/Bitwig/REAPER 都是鼠标尺度）；
- **Live 的自由通道模型**（FL 的 Playlist 轨道默认不与混音轨绑定，按它自己的手册，连 FL 用户都觉得绕）；
- **comping/take 通道、自动化通道、follow action、warp 标记、clip 包络、VST3 托管、多套并存编排**——都需要原生级引擎，或为一个模型里没有的功能引入模式；
- **Amped Studio 的立场**（完整浏览器 DAW 却没有移动模式）——**当时**我们既然有手机目标，就把它当反面；**那个手机外壳已在 `4dffdf0` 砍掉**（手机浏览器现在拿到的是桌面 UI，`docs/OPEN_WORK.md` §十三），所以这一条不再是我们自己的取舍依据。
- **密集的每轨 I/O**：Live 与 Bitwig 都把它做成可选，绝不放进默认轨道头。

## 6. 我们独有的三件事，怎么放才不破坏惯例

1. **采样器/SFZ 乐器槽**：在轨道头上放一个**带名字的乐器 chip**（"SFZ: Salamander Grand"／"Drums: 808"），位置正是 Cubase 放可配置轨道控件、FL 用 Track Mode 绑定乐器的地方。点它打开**乐器抽屉**：SFZ、音域、力度层（我们这套鼓是 31/63/95/127 分层）、虚拟键盘。惯例保持：**乐器属于轨道**，深度只隔一次点击。绝不为它单开一条通道或一个浮窗。
2. **谱面页签**：照抄 REAPER 的规则——"每次看到的是同一批音符……MIDI 编辑器环境也是同一个……一个 MIDI 条目同一时刻只能以一种视图显示"。所以：**一份 `NoteEvent[]`、两种读法、同时只显示一种、命令相同**，并且切换视图不动播放头、不滚动编排、不改选区。页签留在编辑器 dock 里（现在的 `ArrangementViewV2` 已经如此），**绝不放进全局工具栏**。
3. **Agent/MCP 编辑**：没有 DAW 先例可抄，所以呈现为**带出处的普通编辑**，而不是一个模式：agent 的改动走与界面相同的纯函数与同一套撤销栈；受影响的轨道在轨道头上挂一个"agent 已编辑"小标记（本次会话内有效）；底部 dock 的 **Activity 抽屉**用结果语言列出改了什么（"给 Bass 加了 12 个音符"），复用平台既有的 announcer；**播放中 agent 的工作不抢焦点、不滚动时间轴**。**不做"AI 模式"开关**——没有 DAW 用户对它有任何肌肉记忆。

## 7. 键盘与无障碍

**各程序确有冲突**（值得记下以免选错）：播放/停止 Space（Live/Bitwig/REAPER/Soundation/GridSound 一致）；录音 Live 是 `F9` 而 Logic/Soundation 是 `R`；solo `S` 一致；mute Logic/Soundation 是 `M`，Live 是 `Shift+M`（Live 的裸 `M` 是电脑 MIDI 键盘）；切分 `Ctrl/Cmd+E`；合并 `Ctrl/Cmd+J`；复制 `Ctrl/Cmd+D`；缩放到选区 `Z`、退回 `X`（Live）。

**我们取**：Space 播放/停止、`S` solo、`R` 录音、`Ctrl/Cmd+E` 切分、`Ctrl/Cmd+J` 合并、`Ctrl/Cmd+D` 复制、`Ctrl/Cmd+Z`/`Shift+Z`、`Z`/`X` 缩放、方向键微调、Delete。**不用裸 `M` 做 mute**，因为 `M` 要留给虚拟 MIDI 键盘。

**WCAG 2.2 里真正约束这个界面的**：1.3.1、1.4.2、1.4.11、2.1.1、2.2.2、2.4.3、2.4.7、2.4.11、2.5.1、2.5.2、2.5.5、**2.5.7**、2.5.8。**2.5.7（拖动动作）是让"只能靠拖 loop brace / 拖区域"这条路走不通的那条**：每个拖动都必须有单指针的非拖动替代（方向键、数字输入或上下文菜单）。角色上：轨道头每个控件用 `toolbar`/`switch`/`slider`，`grid` 只用于通道，或把通道暴露为区域列表（ARIA APG grid）。

## 8. 落地顺序（按价值排）

| # | 惯例 | 换来什么 | 成本 |

| 2 | 240 px 固定轨道头列 + 通道区，横向滚动同步、纵向各自滚动 | 用户已知的布局，也是标尺对齐的前提 | M |

## 9. 没能核实的（不假装核实了）

- **Studio One**：一手手册没取到（DNS/404/403 都遇到），所以上面是 **7 款里的 6 款**；
- **Logic Pro for Mac 桌面版**的具体控件：Apple 的页面是 JS 渲染的，只拿到标题；所有 Logic 结论都来自**官方 iPad 版手册**并已标注；
- **Cubase**：读到的是 **Elements 13**（Steinberg PDF 的镜像），Pro 版可能有差异；
- **BandLab**（403）、**Soundtrap 帮助中心**（DNS 失败，仅营销页）、**Splice 工具**、**Signals**、**LMMS web 端口**：均未核实；
- **REAPER 是否在编排条目里画音符缩略**：手册没有明确说法，视为未核实；
- **像素/触摸尺寸**：没有任何 DAW 手册规定目标尺寸；44 px 来自 WCAG 2.5.5/2.5.8 与我们自己的习惯，"桌面 24 px、触摸 44 px"的分法**是建议而不是有据可循的惯例**。
